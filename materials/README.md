# MCP на примере TODO-приложения

Практика к теме «MCP, Tools, Skills и AI Automation». Есть маленькое веб-приложение TODO (Flask) и MCP-сервер к нему.
Сервер подключается к агенту [Qwen Code](https://github.com/QwenLM/qwen-code), и агент создаёт, ищет, закрывает и удаляет задачи.
На этом примере разбираются примитивы MCP: **Tools**, **Resources**, **Prompts** и **Elicitation**.

```
apps/todo/               TODO-приложение: UI на / и REST API на /api/*, тесты в tests/
practice/mcp/server.py   MCP-сервер (stdio), ходит в REST API приложения
practice/mcp/test_server.py   тесты сервера, в том числе через настоящий MCP-протокол
practice/agent/.qwen/    настройки Qwen Code (модель и подключение MCP-серверов)
environment.yml          conda-окружение со всеми зависимостями
HOMEWORK.md              домашнее задание
```

| Примитив | Что в сервере |
|---|---|
| Tools | `add_task`, `list_tasks`, `complete_task`, `delete_task` |
| Resources | `todo://tasks/{task_id}`: задача по id в JSON |
| Prompts | свой сценарий, который вы напишете в части 3 |
| Elicitation | `delete_task` спрашивает у пользователя подтверждение перед удалением |

## 1. Окружение

Нужны [conda](https://docs.conda.io/en/latest/miniconda.html) и доступ к LLM по OpenAI-совместимому API (адрес, имя модели и ключ).
Всё остальное ставится в одно окружение: Python, Flask, SDK `mcp`, Node.js с npm, `uv` и сам Qwen Code.

```bash
conda env create -f environment.yml
conda activate aidd-mcp
npm install -g @qwen-code/qwen-code    # попадёт в окружение, не в систему
```

Проверка: `python --version` (3.12), `npm --version`, `qwen --version`.
Предупреждение npm про `audio-capture` можно игнорировать.

Дальше все команды выполняются **в активированном окружении** и из корня репозитория, если не сказано иное.

## 2. Запуск TODO-приложения

```bash
cd apps
python -m todo.web          # порт по умолчанию 5000, --port 5001 меняет его
```

Откройте <http://127.0.0.1:5000>: список обновляется сам раз в 2 секунды, поэтому правки агента видны сразу.
На macOS порт 5000 часто занят AirPlay: тогда запустите с `--port 5001` и везде используйте этот порт (в том числе в `TODO_API_URL`).
Приложение должно работать всё время, пока вы пользуетесь MCP-сервером. Запускайте его в отдельном терминале.

Данные лежат в `todo_db.json` (в папке запуска). Файл подписан ключом (HMAC), поэтому правка вручную сломает подпись, и приложение откажется
читать такую базу и ничего не перезапишет. Ключ берётся из переменной `TODO_SECRET_KEY` или из файла `~/.todo_demo/secret.key`, он создаётся при первом запуске.

Чтобы не заполнять список вручную, добавьте случайные задачи (сроки от -10 до +30 дней или без срока, разные приоритеты, часть уже выполнена).
Приложение должно быть запущено:

```bash
cd apps
python seed.py 20               # 20 задач; --seed 1 даёт один и тот же набор, --url меняет адрес приложения
```

Проверка приложения: `cd apps && python -m unittest discover -s todo/tests -t .`

### REST API

| Запрос | Что делает |
|---|---|
| `GET /api/tasks[?done=true\|false]` | список задач |
| `POST /api/tasks` `{title, priority?, due?}` | создать; `priority`: `low`/`normal`/`high`, `due`: `YYYY-MM-DD` |
| `GET /api/tasks/{id}` | одна задача |
| `PATCH /api/tasks/{id}` `{title?, priority?, due?, done?}` | изменить поля |
| `POST /api/tasks/{id}/complete` | отметить выполненной |
| `DELETE /api/tasks/{id}` | удалить |

Название задачи: пробелы по краям обрезаются, пустое и длиннее 200 символов нельзя. Ошибки приходят как `{"error": "..."}` (400, 404).

## 3. Проверка MCP-сервера без агента

```bash
npx @modelcontextprotocol/inspector "$(which python)" "$PWD/practice/mcp/server.py"
```

Откройте ссылку, которую напечатает Inspector (она с токеном), нажмите **Connect**. Дальше:
- **Tools**: **List Tools**, затем `add_task` с `title` и **Run Tool**. Задача появится в UI;
- **Resources**: **Resource Templates**, затем `todo://tasks/{task_id}` и `task_id = 1`;
- **Prompts**: здесь появится ваш сценарий из части 3;
- **Tools**, затем `delete_task`: появится форма подтверждения (Elicitation).

Пути должны быть абсолютными (отсюда `$(which python)` и `$PWD`), иначе будет ошибка `spawn ... ENOENT`.

## 4. Настройка Qwen Code

Откройте [practice/agent/.qwen/settings.json](practice/agent/.qwen/settings.json) и подставьте модель: имя вместо `<model_name>` и адрес API вместо `<model_url>`.
Ключ в файл не пишется: в `envKey` указано имя переменной окружения `MODEL_API_KEY`, и Qwen читает ключ из неё (`process.env`). Перед запуском задайте её:

```bash
export MODEL_API_KEY=...   # ключ не попадёт в settings.json и в git
```

Можно вместо этого положить ключ в `~/.qwen/.env` (или `.env` в корне проекта) строкой `MODEL_API_KEY=...` и добавить `.env` в `.gitignore`.

Запуск агента (приложение из шага 2 должно работать):

```bash
cd practice/agent
qwen
```

При первом запуске Qwen спросит, доверять ли папке и MCP-серверам: подтвердите (пока этого не сделано, сервер висит в статусе `Pending approval`).
Команда `/mcp` внутри `qwen` показывает подключённые MCP-серверы и их tools.
Флаг `--trust` не используйте: он отключает подтверждения вызовов tools, а их как раз полезно видеть.

**Другие клиенты.** Код сервера один для всех агентов, отличается только конфиг. Elicitation, которого нет в Qwen, можно посмотреть в Claude Code:

```bash
claude mcp add todo -e TODO_API_URL=http://127.0.0.1:5000 -- "$(which python)" "$PWD/practice/mcp/server.py"
```

В OpenCode сервер описывается в `opencode.json` в корне проекта (пути абсолютные), проверка: `opencode mcp list`.

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "todo": {
      "type": "local",
      "command": ["/path/to/python", "/path/to/practice/mcp/server.py"],
      "environment": { "TODO_API_URL": "http://127.0.0.1:5000" },
      "enabled": true
    }
  }
}
```

**1.3. Запретите агенту ходить в сеть: hook.**
Hook запускается самим Qwen перед каждым вызовом tool и работает в любом режиме, в том числе в yolo: это гарантия, а не просьба к модели.
Создайте `practice/agent/.qwen/hooks/guard.py`:

```python
#!/usr/bin/env python3
"""PreToolUse-hook: запрещает сеть из shell, а изменения задач всегда требуют подтверждения."""
import json
import re
import sys

data = json.load(sys.stdin)
tool = data.get("tool_name", "")
args = data.get("tool_input", {})


def decide(decision: str, reason: str) -> None:
    print(json.dumps({"hookSpecificOutput": {
        "hookEventName": "PreToolUse",
        "permissionDecision": decision,          # allow / deny / ask
        "permissionDecisionReason": reason,
    }}, ensure_ascii=False))
    sys.exit(0)


if tool == "run_shell_command":
    cmd = args.get("command", "")
    if re.search(r"\b(curl|wget|nc|ncat)\b|todo_db\.json", cmd):
        decide("deny", "Сетевые команды и прямой доступ к БД запрещены.")

if re.fullmatch(r"mcp__todo__(complete_task|delete_task)", tool):
    decide("ask", f"Изменение задач: {tool} {json.dumps(args, ensure_ascii=False)}")

decide("allow", "ok")  # обычные проверки и подтверждения Qwen остаются в силе
```

Подключите его в `practice/agent/.qwen/settings.json` (на верхнем уровне, рядом с `model`). MCP-tools в Qwen называются `mcp__<сервер>__<tool>`, shell-команды идут через `run_shell_command`:

```json
"hooks": {
  "PreToolUse": [
    {
      "matcher": "^(run_shell_command|mcp__todo__.*)$",
      "hooks": [
        {
          "type": "command",
          "command": "python \"$QWEN_PROJECT_DIR/.qwen/hooks/guard.py\"",
          "name": "todo-guard",
          "timeout": 10
        }
      ]
    }
  ]
}
```

Вторая проверка (`mcp__todo__…`) пока не срабатывает: она пригодится, когда в 1.7 подключим MCP-сервер.
Hooks проекта загружаются только в доверенной папке. Команда `/hooks` показывает подключённые hooks и перечитывает настройки после правок.

Перезапустите `qwen` (или откройте `/hooks`) и повторите просьбы из 1.2. Что изменилось? Попробовал ли агент обойти запрет другим способом
(например, через `python -c "import urllib.request; ..."`)? К этому вопросу вернёмся в [ДЗ](HOMEWORK.md).

> **Подтверждения.** Hook из 1.3 спрашивает подтверждение на `complete_task` и `delete_task` в любом режиме, даже с `--approval-mode yolo`.

### Часть 5. Агент в изолированном окружении

Агента не обязательно запускать прямо на своём компьютере: его можно гонять в контейнере, а shell-команды агента будут выполняться внутри него.
По умолчанию из контейнера видно не всё: только то, что вы явно смонтировали. Файла базы `todo_db.json`, ключа `~/.todo_demo/secret.key`,
вашего `$HOME` и остального диска там нет.

**5.1. Соберите образ** с Python, Node.js, Qwen Code и зависимостями MCP-сервера (из корня репозитория, один раз, ~1-2 минуты):

```bash
docker build -t qwen-agent - <<'EOF'
FROM node:22-bookworm-slim
RUN apt-get update \
 && apt-get install -y --no-install-recommends python3 python3-venv ca-certificates \
 && rm -rf /var/lib/apt/lists/*
RUN python3 -m venv /opt/venv && /opt/venv/bin/pip install --no-cache-dir "mcp>=1.9,<3" "flask>=3.0" uv
ENV PATH="/opt/venv/bin:$PATH"
RUN npm install -g @qwen-code/qwen-code
USER node
WORKDIR /workspace
ENTRYPOINT ["qwen"]
EOF
```

**5.2. Сделайте настройки для контейнера.** Внутри контейнера пути другие, поэтому `settings.json` с путями вашего компьютера не подойдёт.
Сделайте копию `practice/agent/.qwen/settings.docker.json`: те же настройки модели, но другой `mcpServers`:

```json
"mcpServers": {
  "todo": {
    "command": "python",
    "args": ["/opt/todo-mcp/server.py"],
    "env": { "TODO_API_URL": "http://host.docker.internal:5000" }
  }
}
```

**5.3. Запустите агента.** Приложение запускается на хосте как обычно (шаг 2), агент — в контейнере (из корня репозитория):

```bash
export MODEL_API_KEY=...            # ключ не записывается ни в образ, ни в файл
docker run --rm -it \
  -v "$PWD/practice/agent:/workspace" \
  -v "$PWD/practice/mcp:/opt/todo-mcp:ro" \
  -v "$PWD/practice/agent/.qwen/settings.docker.json:/workspace/.qwen/settings.json:ro" \
  -e MODEL_API_KEY \
  qwen-agent
```

Что здесь происходит:
- `practice/agent` монтируется в `/workspace`, это рабочая папка агента, и всё, что он там создаёт (например, `reports/`), остаётся у вас на диске;
- `practice/mcp` монтируется только для чтения: агент может запустить сервер, но не может его изменить;
- `settings.docker.json` подставляется поверх `settings.json` только внутри контейнера, файл на диске не меняется;
- к приложению на хосте контейнер ходит по адресу `host.docker.internal`.

**5.4. Проверьте, что видит агент.** Попросите его выполнить `ls /Users`, `cat ~/.todo_demo/secret.key`, `cat todo_db.json`: ничего этого в контейнере нет.
Затем `/mcp` (сервер `todo` должен быть подключён) и «покажи задачи»: работа с задачами идёт как обычно, через MCP.

Ограничения: сеть из контейнера по умолчанию открыта (модель тоже доступна только через сеть), её при необходимости ограничивают отдельно.
Проверено в Docker Desktop (macOS). На Linux добавьте к `docker run` флаг `--add-host=host.docker.internal:host-gateway` и `--user "$(id -u):$(id -g)"`,
а приложение должно быть доступно не только на `127.0.0.1`.

### Часть 6. Автоматизация в n8n

[n8n](https://n8n.io) — open-source платформа автоматизации: вы собираете процесс из готовых блоков,
а не пишете его кодом. Полезна, когда шаги известны заранее и процесс должен быть предсказуемым (в отличие от агента).
Развернуть можно в облаке (n8n Cloud) или у себя (Docker). Мини-инструкция ниже — только основные моменты, подробности на официальном сайте.

**Как строить воркфлоу.**
- Воркфлоу — это граф из **нод**, соединённых стрелками; данные текут от ноды к ноде слева направо.
- Любой воркфлоу начинается с **триггера** — он запускает процесс: вебхук, форма, расписание, входящее письмо или сообщение.
- Дальше идут **ноды-действия**: HTTP-запрос, запись в таблицу или базу, отправка сообщения, вызов LLM. Для разветвления — ноды **IF** и **Switch**.
- Между нодами видно, какие поля пришли; в параметрах следующей ноды на них ссылаются через выражения (`{{ $json.поле }}`).
- Отлаживать удобно кнопкой **Execute** (прогнать воркфлоу или отдельную ноду) и смотреть вход/выход каждой ноды.

**Где хранить секреты.**
- Все ключи, токены и пароли храните **только в разделе Credentials**, а не в параметрах нод.
- Нода ссылается на Credentials по имени; при экспорте воркфлоу в JSON сами секреты в файл не попадают.
- Правило простое: если ключ виден в параметрах ноды или в экспортированном JSON — это ошибка.

Тесты сами поднимают приложение и проверяют сервер напрямую и через stdio-протокол, включая Elicitation и Resource.

| Проблема | Что проверить |
|---|---|
